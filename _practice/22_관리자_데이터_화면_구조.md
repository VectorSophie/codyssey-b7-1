# 🟩 관리자 데이터 화면 구조

## 🟢 SQLite 세 테이블

### 🟡 users

- `id`: 사용자를 구별하는 번호
- `username`: 로그인 이름
- `email`: 이메일 개인정보
- `created_at`: 가입 시각
- `password_hash`: DB에는 있지만 관리자 API와 화면에서 제외하는 인증 비밀

### 🟡 chat_sessions

- `id`: 대화방 번호
- `user_id`: 대화방 주인의 사용자 번호
- `title`: 대화 제목
- `created_at`, `updated_at`: 생성·수정 시각

### 🟡 messages

- `id`: 메시지 번호
- `session_id`: 메시지가 속한 대화방 번호
- `role`: `user` 질문 또는 `assistant` 답변
- `content`: 질문·답변 원문
- `request_id`, `status`, `latency_ms`: 요청 추적과 처리 상태
- `created_at`: 메시지 생성 시각

## 🟢 화면에서 관계를 읽는 방법

`user_id`와 `session_id`는 데이터 사이를 연결하는 주소와 같다.

1. 메시지의 `session_id`로 대화방을 찾는다.
2. 대화방의 `user_id`로 사용자를 찾는다.
3. 화면은 메시지 옆에 사용자 이름, 이메일, 대화 제목을 함께 보여준다.

## 🟢 화면 기능

- 요약 카드: 사용자·대화방·메시지 수와 최근 메시지 시각
- 탭: 세 테이블을 한 번에 섞지 않고 각각 확인
- 검색: ID, 사용자 이름, 이메일, 제목, 메시지 원문, 요청 ID 검색
- 상세 펼치기: 긴 질문과 답변을 잘리지 않은 원문으로 확인
- 새로고침: 현재 DB 상태를 서버에서 다시 요청

## 🟢 관련 파일

- `app/services/admin.py`: DB 전체 행 조회
- `app/routers/admin.py`: 인증된 관리자 HTTP API
- `frontend/src/api/client.ts`: JSON을 TypeScript 자료로 검사·변환
- `frontend/src/pages/AdminPage.tsx`: 관리자 화면과 검색 동작
- `frontend/src/styles.css`: 표, 탭, 모바일 화면 모양
