# 🟩 관리자 권한과 API 흐름

## 🟢 이번 기능의 목표

관리자는 로그인한 뒤 `/admin` 화면에서 SQLite의 사용자, 대화방, 메시지를 확인한다.
일반 사용자는 같은 주소를 입력해도 개인정보를 받을 수 없다.

## 🟢 권한은 두 번 나누어 생각한다

### 🟡 화면 표시용 권한

로그인 응답의 `is_admin`은 관리자 메뉴를 보여줄지 판단하는 표지판이다.
표지판은 사용하기 편하게 만들 뿐 실제 문을 잠그지는 않는다.

### 🟡 서버의 실제 권한

`app/dependencies.py`의 `require_admin`은 관리자 API 요청이 올 때마다 다음 순서로 검사한다.

1. 로그인 쿠키가 유효한지 확인한다.
2. 현재 사용자 이름이 `ADMIN_USERNAMES` 목록에 있는지 확인한다.
3. 모두 맞을 때만 DB 데이터를 반환한다.

브라우저의 값은 사용자가 바꿀 수 있으므로 서버는 `is_admin` 값을 믿지 않는다.

## 🟢 요청 흐름

1. `app/routers/auth.py`가 로그인 사용자를 확인한다.
2. 서버가 공개 가능한 사용자 정보와 `is_admin`을 보낸다.
3. `frontend/src/auth/AuthContext.tsx`가 현재 사용자를 기억한다.
4. 관리자라면 일반 화면에 관리자 링크가 나타난다.
5. `/admin`이 `/api/admin/database`를 요청한다.
6. 서버가 `require_admin`으로 권한을 다시 검사한다.
7. 허용된 관리자에게만 세 테이블 데이터를 보낸다.

## 🟢 보안 핵심

- `.env` 내용과 API Key는 화면이나 로그에 출력하지 않는다.
- `password_hash`는 비밀번호 원문이 아니어도 인증 비밀이므로 반환하지 않는다.
- 관리자 응답에 캐시 금지 헤더를 넣어 개인정보가 브라우저 캐시에 남는 위험을 줄인다.
- HTML 문자열을 직접 삽입하지 않고 React 텍스트 렌더링을 사용해 XSS 공격을 막는다.
