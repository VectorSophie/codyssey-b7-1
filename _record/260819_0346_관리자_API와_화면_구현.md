# 🟩 관리자 API와 화면 구현 기록

## 🟢 작업 목적

Issue #15에서 관리자가 SQLite의 사용자 개인정보, 대화방, 질문·답변 로그를
직관적으로 확인하도록 관리자 전용 API와 React 화면을 구현했다.

## 🟢 기존 문제

- `/api/admin/logs`는 최근 50개 메시지만 제공했다.
- 사용자 ID, 이메일, 메시지 ID, 대화방 시각 정보가 부족했다.
- 사용자와 대화방 전체 행을 조회하는 관리자 API가 없었다.
- 관리자가 사용할 화면이 없었다.
- 관리자 개인정보 응답의 캐시 금지 정책이 명시되지 않았다.

## 🟢 구현 내용

### 🟡 백엔드

- `/api/admin/logs`가 제한 없이 전체 결합 로그를 반환하도록 변경했다.
- `/api/admin/database`가 `users`, `chat_sessions`, `messages` 전체 행을 반환한다.
- 사용자·대화방·메시지의 기본키와 외래키를 포함해 관계를 추적할 수 있게 했다.
- 로그인 응답에 화면 표시용 `is_admin`을 추가했다.
- 모든 관리자 API 요청은 서버의 `require_admin`을 통과해야 한다.
- 관리자 응답에 `Cache-Control: no-store, private`와 `Pragma: no-cache`를 추가했다.

### 🟡 프론트엔드

- `/admin` 보호 경로와 관리자 전용 메뉴를 추가했다.
- 세 테이블 요약 카드, 탭, 검색, 새로고침, 상세 메시지 펼치기를 구현했다.
- 401은 로그인 후 `/admin` 복귀로 처리한다.
- 403은 개인정보를 지우고 권한 부족 안내만 표시한다.
- 좁은 화면에서는 표를 가로 스크롤할 수 있게 했다.

## 🟢 보안 검토

- `.env`와 실제 비밀값을 읽거나 출력하지 않았다.
- `password_hash`는 API 스키마와 화면에서 제외했다.
- 일반 사용자 403 테스트에서 이메일·메시지가 화면에 없는지 확인했다.
- React 텍스트 출력만 사용하고 위험한 HTML 삽입 기능은 사용하지 않았다.
- 프론트엔드의 `is_admin`은 메뉴 표시에만 사용하고 서버가 권한을 재검사한다.
